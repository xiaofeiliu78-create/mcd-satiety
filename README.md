# 麦门顶饿算账

> **花同样的钱，谁更顶饿？谁更容易胖？**
> 用麦当劳中国官方 MCP 的真实门店菜单 + 官方营养数据，算出这一单该怎么点。

跑一条命令，输出长这样：

> 35 块 800 大卡，点薄皮焦香V翅×2，384 大卡 34 克蛋白，比培根安格斯厚牛堡省 3 块 5、少 323 大卡。

---

## 三分钟跑起来

### 第 1 步：领一个 Token（只做一次，约 1 分钟）

1. 手机或电脑打开 <https://open.mcd.cn/mcp>
2. 点右上角「登录」，手机号 + 验证码登录
3. 点右上角「控制台」→「激活」→ 同意协议
4. Token 立刻生成，复制那串字符

### 第 2 步：把 Token 配到本机（三种方式，任选一种）

| 系统 | 命令 | 说明 |
|---|---|---|
| Windows 临时 | `set MCD_MCP_TOKEN=你的Token` | 只对当前窗口有效 |
| Windows 永久 | `setx MCD_MCP_TOKEN 你的Token` | 设完要关掉命令行窗口重开 |
| macOS / Linux | `export MCD_MCP_TOKEN=你的Token` | 想长期生效就写进 `~/.zshrc` |

也可以不改环境变量，直接在 `~/.workbuddy/mcp.json` 里配一个 `mcd-mcp` 连接器，`Authorization` 填 `Bearer 你的Token`，脚本会自动去读。仓库里的 [`mcp-config.example.json`](mcp-config.example.json) 是现成模板。

### 第 3 步：跑

| 系统 | 怎么做 |
|---|---|
| **Windows** | 双击仓库里的 **`一键算账.bat`**，按提示填城市 / 门店 / 预算 / 热量，一路回车就出结果 |
| **macOS / Linux** | 终端里 `sh run.sh`，同样按提示填。想双击运行，把文件名改成 `run.command` |
| **任意系统（一条命令）** | `python mcd_solver.py --city 周口市 --budget 35 --kcal 800` |

只需要 Python 3（系统自带的那种就行），**不需要装任何第三方库**。

## 参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--city` | 城市 | 周口市 |
| `--keyword` | 商圈 / 门店关键词。**不给就列出全部门店让你选** | 空（自动找最近） |

| `--oneline` | 只输出一句话，方便发微信 | 关 |
| `--json` | 输出结构化数据，方便接到别的地方 | 关 |

## 它解决什么问题

麦当劳官方有营养表，也有价格，但**从不告诉你这两件事**：

- 每块钱能换多少克蛋白质？
- 同样吃到 30 克蛋白，哪种点法热量最低？

因为营养表和价目表在麦当劳内部是两套数据，天生不互通。本项目把这两套数据**按商品名精确对齐**，然后缝起来算账。

## 算出来的东西反直觉

同样吃 **300 大卡**：

| 选择 | 蛋白 |
|---|---|
| 薄皮焦香V翅 | **27 g** |
| 脆薯饼 | **2 g** |

**差 12.9 倍。** 同一个胃，装的完全不是同一种东西。

再举个真实场景（周口文昌万达店，预算 ¥35 / 800 kcal）：

> 同样吃到约 **34 g 蛋白**：
> `薄皮焦香V翅 × 2` 只要 **384 kcal**（¥31）
> `培根安格斯厚牛堡 × 1` 要 **707 kcal**（¥34.5）
> 差的这 **323 kcal**，差不多是**慢跑 32 分钟**。
>
> 两单蛋白一样多，钱差不多，热量差出一个慢跑的量。

**最「减脂」的不是汉堡，是炸鸡翅。** 这是人的直觉猜不到的答案，也是这个工具的价值。

## 三个指标，全部可解释

| 指标 | 公式 | 回答什么 |
|---|---|---|
| 每元蛋白 | 蛋白(g) ÷ 价格(元) | 省钱 |
| 蛋白密度 | 蛋白(g) ÷ (热量 kcal / 100) | 又顶饿又不增肥 |
| 钠占比 | 钠(mg) ÷ 2000mg | 会不会水肿、假性增重 |

**为什么锁定蛋白质：** 它同时干三件事——最压饿（饱腹感最强）、消化它本身要耗掉 20-30% 的热量（食物热效应）、减脂时不掉肌肉。所以「又顶饿又不增肥」在物理上就落在 `蛋白 ÷ 热量` 这个比值上。

刻意**不做加权综合分**。每个指标都能单独讲清楚，不用黑箱分数唬人。

另外，「吃最饱不胖」这一档额外要求**组里每一件单品**的蛋白密度都 ≥ 3.0，否则会出现「一个正经汉堡 + 一个圆筒冰淇淋」这种为了凑蛋白数字而掺水的组合。

## 已知边界（老实说）

- **只能算菜单里的一小部分。** 营养库 160 条与门店菜单做**精确同名**匹配，当前实测能算 **20 个单品**（建表时的快照是 19 个，会随菜单上下架浮动）。对不上的**不做估算、不猜、不外推**。宁可少给，不给假数。
- **套餐算不了。** 「XX 三件套」这类没有营养数据，所以只算单品自由组合。
- **不依赖优惠券。** 实测部分账号的卡包券接口返回空数组，为保证结果可靠，本工具不把券纳入计算。
- **不下单。** 所有下单类工具永不主动调用，只算账，不花钱。
- **只算单品价格，不含配送费。** 到店和外卖的最终价可能有差。

## 另外两种用法

### 作为 WorkBuddy Skill（实时查任意门店）

把本仓库放进 `~/.workbuddy/skills/mcd-satiety/`，然后在 WorkBuddy 里直接说：

> 我今晚想吃麦当劳，预算 35，别超过 800 大卡，怎么点最顶饿？

这个 Skill **自带双模式**，本机有没有 Python 都能跑：

| 模式 | 条件 | 算法 |
|---|---|---|
| A 精确 | 本机有 Python | 全量枚举符合预算与热量的组合，取最优 |
| B 零依赖 | 没有 Python 也能用 | 直接用 mcd-mcp 连接器工具 + `data/mapping.json` 对齐表，贪心选档 |

模式 B 是个兜底——**宁可给一个标明是贪心的答案，也不能因为环境没装好就说做不了。**

### 网页演示（手机浏览器打开就能看）

[`web/index.html`](web/index.html) 是单文件网页，纯前端、不联网、不含 Token，手机浏览器打开即可，还能「添加到主屏幕」当图标。在线版：<https://xiaofeiliu78-create.github.io/mcd-satiety/>

拖预算 / 热量两个滑杆，三档答案与单品效率榜实时重算。

> **它是快照，不是实时。** 页面内置的是 2026-10-24 12:18 通过官方 MCP 抓取的门店数据，不会自己更新。为什么不做实时：实时计算需要服务端持有 Token，等于把账号交给所有访客调用。**要查自己附近的门店、看今天的真实价格，请用上面的脚本。**

网页里的算账逻辑与 `mcd_solver.py` 是同一套目标函数，已用 Node 逐一比对四个预算区间，结果完全一致。

## 技术架构

```
mcd_solver.py          算账引擎
  ├── 定门店        → MCP query-nearby-stores（按城市列出 + 距离排序）
  ├── 取菜单价格    → MCP query-meals
  ├── 取营养数据    → MCP list-nutrition-foods
  ├── 名称对齐      → 只保留精确同名的单品
  ├── 组合枚举      → 预算 + 热量双约束下的组合搜索
  └── 实价复核      → MCP calculate-price（金额单位：分）

mcd_client.py          零依赖 MCP 客户端（仅用标准库）
run.sh                 macOS / Linux 交互式启动
run.ps1 + 一键算账.bat  Windows 交互式启动
web/index.html         手机版网页（单文件，纯前端，同一套算法）
```

零第三方依赖，Python 3.8+ 可跑。MCP 集成细节与踩坑记录见 [`MCP_INTEGRATION.md`](MCP_INTEGRATION.md)。

# 麦门顶饿算账

> **花同样的钱，谁更顶饿？谁更容易胖？**
> 用麦当劳中国官方 MCP 的真实门店菜单 + 官方营养数据，算出三种人设最优的一单。

---

## 两种形态，别搞混

| 形态 | 在哪 | 能干什么 | 限制 |
|---|---|---|---|
| **网页演示** | [`docs/index.html`](docs/index.html)（[在线打开](https://xiaofeiliu78-create.github.io/mcd-satiety/)） | 拖预算 / 热量两个滑杆，立刻看到三档答案与单品效率榜 | 数据是**快照**（2026-10-24 12:18，一家店 19 个单品），不联网、不实时 |
| **命令行 / Skill** | `mcd_solver.py` + `SKILL.md` | 真调麦当劳官方 MCP，**任意城市任意门店、实时价格** | 需要 Python + MCP Token |

一句话：**想立刻看效果 → 点网页；想天天用它帮你决定吃啥 → 跑脚本。**

- Windows 用户：双击仓库里的 **`一键算账.bat`**，按提示填城市 / 门店 / 预算 / 热量，回车就出结果
- 让 AI 帮你算：把仓库放进 `~/.workbuddy/skills/mcd-satiety/`，直接问「麦当劳 35 块 800 大卡怎么点最顶饿」

## 它解决什么问题

麦当劳官方有营养表，也有价格，但**从不告诉你这两件事**：

- 每块钱能换多少克蛋白质？
- 同样吃到 30 克蛋白，哪种点法热量最低？

因为营养表和价目表在麦当劳内部是两套数据，天生不互通。本项目把这两套数据**缝起来算账**。

## 算出来的东西反直觉

同样吃 **300 大卡**：

| 选择 | 蛋白 |
|---|---|
| 薄皮焦香V翅 | **27 g** |
| 脆薯饼 | **2 g** |

**差 12.9 倍。** 同一个胃，装的完全不是同一种东西。

再举个真实场景（周口文昌万达店，预算 ¥35 / 800 kcal）：

> 同样吃到约 **34 g 蛋白**：
> `薄皮焦香V翅 × 2` 只要 **384 kcal**（¥31）
> `培根安格斯厚牛堡 × 1` 要 **707 kcal**（¥34.5）
> 差的这 **323 kcal**，差不多是**慢跑 32 分钟**。
>
> 两单蛋白一样多，钱差不多，热量差出一个慢跑的量。

**最「减脂」的不是汉堡，是炸鸡翅。** 这是人的直觉猜不到的答案，也是这个工具的价值。

## 输出什么

三种人设，三档答案（真实运行结果，完整版见 [`docs/sample-output.md`](docs/sample-output.md)）：

### 吃最饱不胖 — 热量预算内，蛋白最多
`薄皮焦香V翅 × 2`｜实付 ¥31｜384 kcal｜蛋白 34 g｜钠 1188 mg（占日额度 59%）

### 每块钱蛋白最多 — 不看热量只看钱
`双层深海鳕鱼堡 × 1`｜实付 ¥24｜485 kcal｜蛋白 28 g｜每元 1.17 g 蛋白

### 过嘴瘾还不亏 — 要炸的，但也别光吃油
`培根安格斯厚牛堡 × 1`｜实付 ¥34.5｜707 kcal｜蛋白 34 g

外加一张**单品效率榜**（按蛋白密度排序），和一句可直接转发的结论。

## 三个指标，全部可解释

| 指标 | 公式 | 回答什么 |
|---|---|---|
| 每元蛋白 | 蛋白(g) ÷ 价格(元) | 省钱 |
| 蛋白密度 | 蛋白(g) ÷ (热量 kcal / 100) | 又顶饿又不增肥 |
| 钠占比 | 钠(mg) ÷ 2000mg | 会不会水肿、假性增重 |

**为什么锁定蛋白质：** 它同时干三件事——最压饿（饱腹感最强）、消化它本身要耗掉 20-30% 的热量（食物热效应）、减脂时不掉肌肉。所以「又顶饿又不增肥」在物理上就落在 `蛋白 ÷ 热量` 这个比值上。

刻意**不做加权综合分**。每个指标都能单独讲清楚，不用黑箱分数唬人。

## 怎么用

### 方式一：手机浏览器直接打开（推荐给普通用户）

`web/index.html` 是一个**单文件网页**，纯前端、不联网、不含 Token，用手机浏览器打开就能用，还能「添加到主屏幕」当图标。

页面内置的是 2026-10-24 12:18 通过官方 MCP 实时抓取的门店快照（周口文昌万达店，19 个单品），拖动预算和热量两个滑杆，三档答案实时重算。

> 为什么网页是快照而不是实时：实时计算需要服务端持有 Token，而把 Token 放在服务端意味着任何人都能通过你的账号调用接口。为了不碰这个风险，网页版用快照 + 前端实时计算。**要做实时查询请用方式二。**

### 方式二：作为 WorkBuddy Skill（实时查任意门店）

把本仓库放进 `~/.workbuddy/skills/mcd-satiety/`，然后在 WorkBuddy 里直接说：

> 我今晚想吃麦当劳，预算 35，别超过 800 大卡，怎么点最顶饿？

这个 Skill **自带双模式**，本机有没有 Python 都能跑：

| 模式 | 条件 | 算法 |
|---|---|---|
| A 精确 | 本机有 Python | 全量枚举符合预算与热量的组合，取最优 |
| B 零依赖 | 没有 Python 也能用 | 直接用 mcd-mcp 连接器工具 + `data/mapping.json` 对齐表，贪心选档 |

模式 B 是个兜底——**宁可给一个标明是贪心的答案，也不能因为环境没装好就说做不了。**

### 方式三：命令行直接跑


```bash
python mcd_solver.py --city 周口市 --keyword 万达广场 --budget 35 --kcal 800
```

参数：

| 参数 | 说明 | 默认 |
|---|---|---|
| `--city` | 城市 | 周口市 |
| `--keyword` | 商圈 / 门店关键词 | 万达广场 |
| `--store` | 直接指定 storeCode，跳过搜索 | 空 |
| `--budget` | 预算（元） | 35 |
| `--kcal` | 热量上限（0 表示不限） | 800 |
| `--max-items` | 最多几件商品 | 3 |
| `--json` | 输出结构化数据 | 关 |

### 先决条件：MCP Token

1. 手机号登录 https://open.mcd.cn/mcp
2. 右上角「控制台」→「激活」→ 复制 Token
3. 配置（二选一）：
   - 环境变量 `MCD_MCP_TOKEN`
   - 或在 `~/.workbuddy/mcp.json` 配好 `mcd-mcp` 连接器（脚本会自动读取）

## 技术架构

```
mcd_solver.py          算账引擎
  ├── 定门店        → MCP query-nearby-stores
  ├── 取菜单价格    → MCP query-meals
  ├── 取营养数据    → MCP list-nutrition-foods
  ├── 名称对齐      → 只保留精确同名的单品
  ├── 组合枚举      → 预算 + 热量双约束下的组合搜索
  └── 实价复核      → MCP calculate-price（金额单位：分）

mcd_client.py          零依赖 MCP 客户端（仅标准库）
web/index.html         手机版网页（单文件，纯前端，同一套算法）
```

`web/index.html` 里的算账逻辑与 `mcd_solver.py` 是同一套目标函数，已用 Node 逐一比对四个预算区间，结果完全一致。

零第三方依赖，Python 3.8+ 可跑。MCP 集成细节与踩坑记录见 [`MCP_INTEGRATION.md`](MCP_INTEGRATION.md)。

## 已知边界（老实说）

- **只算 19 个单品。** 营养库 160 条与门店菜单 92 条，精确同名交集为 19 个。对不上的**不做估算、不猜、不外推**。宁可少给，不给假数。
- **套餐算不了。** 「XX 三件套」这类没有营养数据，所以只算单品自由组合。
- **不依赖优惠券。** 实测部分账号的卡包券接口返回空数组，为保证结果可靠，本工具不把券纳入计算。
- **不下单。** 所有下单类工具永不主动调用，只算账，不花钱。
